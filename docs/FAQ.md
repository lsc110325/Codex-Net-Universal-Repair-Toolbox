# 常见问题 / FAQ

## Q1 提示"当前很可能运行在 Codex 沙箱内，请直接双击运行"

Codex 沙箱会隔离注册表与配置写入。请在**资源管理器**中双击 EXE，不要从 Codex 终端启动。

## Q2 自检提示"当前进程代理环境"未加载

正常现象。环境变量只对**新进程**生效，请完全退出并重启 Codex（或直接点【重启 Codex】）后再次自检。

## Q3 沙箱内 `curl` 的 HTTPS 报 `SEC_E_NO_CREDENTIALS`

这是 Windows 沙箱对 schannel 的限制，与代理配置无关（HTTP 正常）。需要 HTTPS 时请使用 `git`、`node` 或 Python；本工具已把 **git** 切换到 openssl 后端。

## Q4 自动探测不到端口

- 确认代理软件已启动，并开启了"混合端口/允许局域网"
- 关闭代理软件的"系统代理"不影响本工具探测（工具直接测端口）
- 也可在界面手动填写端口后点【一键修复】

## Q5 修复后一段正常，过一会又断了

检查代理节点是否掉线。工具的后台监控（设置 → 后台监控代理健康）会在**掉线/恢复**时弹托盘提醒。

## Q6 自检 / 端到端失败怎么判断原因？

看探针原始输出：

| 输出 | 含义 | 处理 |
|---|---|---|
| `HTTP/1.1 502` | 代理节点无法出网 | 换节点 |
| `TLS connect error: ... unexpected eof` | 节点被中断 | 换节点 |
| `'remote-https' is not a git command` | `GIT_EXEC_PATH` 未注入 | 重新一键修复 |
| `schannel: SEC_E_NO_CREDENTIALS` | git 仍用 schannel | 重新一键修复（切 openssl） |

## Q7 会不会弄坏我的配置？

不会。所有改动前都会生成带时间戳的备份，点【还原备份】即可回到修复前；工具只修改**当前用户**的配置。

## Q8 如何升级到新版本？

用新版 EXE **直接覆盖**旧版即可（配置与修复结果保留）；旧版本文件夹可用【设置 → 清理旧版本】删除。

## Q9 为什么首次运行会弹更新提示？

用于告知本次更新内容。可以选择：

- **我知道了**：本次关闭，下次版本更新再提示
- **不再提醒**：不再弹提示条，但左侧栏保留**红色【更新提示】胶囊**，随时可点开查看
